# 数据结构重学计划

## 为什么"学过但想不起来"

看懂 ≠ 会写。看讲解是**阅读理解**，从空白文件默写是**回忆提取**，这两条神经通路完全不同。
只做过前者，大脑会产生"我懂了"的错觉，但真到要用的时候调不出来。

解决办法只有一个：**每个结构都从零手写实现，并让测试跑通。**

## 目录规划

```
ds/
├── README.md              本文件（进度表 + 复习节奏）
├── 01-linked-list/        链表
├── 02-stack-queue/        栈与队列
├── 03-binary-tree/        二叉树
├── 04-graph/              图
└── 05-sort/               排序算法
```

每个目录下固定三个东西：

| 文件 | 作用 |
|---|---|
| `xxx.cpp` | 实现 + 测试，一个文件搞定，能直接编译运行 |
| `notes.md` | 我的理解、易错点、复杂度分析（**用自己的话写**） |
| — | 没写的操作留 `TODO`，写完一个删一个 |

## 每个结构的固定流程（四步）

1. **先看一遍原理**（教材 / 视频，不超过 30 分钟，不要陷进去）
2. **合上资料，从空白文件写实现**，卡住就记下来，不要立刻翻答案
3. **跑测试**：`build.bat 01-linked-list\list.cpp`，然后 `.\build\list.exe`
   - 全绿 → 这一步过关
   - 有红 → 说明边界没考虑到，这恰恰是最有价值的部分
4. **提交**：`git add .` → `git commit -m "feat(list): 实现 push_back 和 remove"` → `git push`

## 复习节奏（防遗忘）

| 时间点 | 做什么 |
|---|---|
| 学完当天 | 完成实现 + 测试通过 + 提交 |
| 第 3 天 | **闭卷重写**核心操作（不看之前的代码），对比差异 |
| 第 7 天 | 不看代码，口头讲一遍原理 + 手写复杂度 |
| 第 15 天 | 用 `git log --follow 文件名` 翻出自己当时的代码，重读一遍 |

**关键：复习是"重写"和"回忆"，不是"重读"。** 重读会产生虚假的熟悉感，重写才知道哪里真空着。

## 和 Git 结合的四条用法

1. **细粒度提交**：每实现一个操作就提交一次。三个月后 `git log` 就是你的学习轨迹，比任何笔记都真实。
2. **提交信息用固定格式**：`feat(list): 实现 push_back`，一看就知道做了什么。改 bug 用 `fix(list): 修正删除头节点时 size 未减`。
3. **里程碑打标签**：一个结构全部做完，`git tag v1-list`。以后回看很方便。
4. **每周日回顾**：`git log --oneline --since="1 week ago"`，看到一周的提交，比"感觉这周啥也没干"真实得多。

## 提醒

- 一次只攻一个结构，不要同时开三个。
- 每个结构的**第一遍允许写得丑**，先跑通再说优化。
- 写不出来是正常的。写不出来还硬撑着不查资料，那才是浪费时间——卡 15 分钟以上就去看提示，但看完必须**关掉资料重写一遍**。
